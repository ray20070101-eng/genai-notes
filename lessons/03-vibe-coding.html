Vibe Coding：用說的把網頁做出來

我負責描述需求和驗收，AI 負責寫程式。

本週重點

  • Vibe Coding：用自然語言描述想要的功能，讓 AI 產生程式碼。
  • 重點從「會不會寫」變成「說不說得清楚、驗不驗得出問題」。
  • 單一 index.html 最容易部署，直接丟 GitHub Pages。
  • 繳交要有網站連結、介面截圖和規格說明。

核心概念

Vibe Coding 的循環是：描述 → 產生 → 執行 → 回報問題 → 修改。AI 寫得很快，但它不知道你腦中的畫面，所以要給具體的情境，例如「手機上按鈕太小」比「排版怪怪的」有用很多。

做好後用 GitHub Pages 免費發布：repo 的 Settings → Pages 選 main 分支，就有一個公開網址。

比喻像跟室內設計師溝通：你不用會木工，但要說得出想要的風格，還要會驗收哪裡不對。

實作流程

  1. 先寫一段規格：這個網頁給誰用、有哪些功能、畫面長怎樣。
  2. 請 AI 產生單一 index.html。
  3. 本機打開測試，把錯誤或不滿意的地方具體描述回去。
  4. 重複到功能完整。
  5. 上傳 GitHub，開啟 Pages，截圖並寫規格說明。

我的作業

我做了 AutoDM：IG 留言自動私訊的設定器＋模擬器。創作者設定關鍵字（例如「食譜」），有人留言觸發就送出預設私訊。只做前端模擬，沒有真的串 IG。

踩雷與提醒

AI 改 A 壞 B每次修改後整個流程都要重測一次，不要只測剛改的地方。
Vibe Coding 很難「接著做」每次對話 AI 都不記得之前的規則，風格容易跑掉——這就是之後要寫 CLAUDE.md 的原因。
