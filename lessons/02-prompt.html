第4週 Prompt

和 AI 一起設計好用的 Prompt

從一句直覺的指令，迭代成換到哪個 LLM 都能用的 Prompt。

本週重點

  • Prompt 就是你給 LLM 的指令，品質直接決定輸出品質。
  • 好 Prompt 要說清楚：角色、任務、讀者、語氣、長度、格式、成功標準。
  • 可以請 AI 反問你問題，把需求問清楚再寫。
  • 最後的 Prompt 要能「帶著走」，在至少 3 個 LLM 測試結果都穩定。

核心概念

LLM（大型語言模型）其實是在猜「下一個字最可能是什麼」，所以你給的脈絡越完整，它猜得越準。直覺寫的 Prompt 通常太短，AI 只能自己腦補。

比較好的流程是：先寫直覺版 → 請 AI 產生草稿 → 讓 AI 列出它需要知道的問題 → 回答後整合成可攜式 Prompt。

比喻像點飲料：只說「一杯茶」店員會亂做；說「大杯四季春、微糖少冰」才會拿到你要的那杯。

實作流程

  1. 寫下最直覺的 Prompt，例如「幫我寫一篇介紹我自己做的 unity 開發文章」。
  2. 讓 AI 先寫一版，觀察哪裡不是你要的。
  3. 請 AI 反問：讀者是誰？語氣？長度？要強調什麼？
  4. 把答案整理成結構化的最終 Prompt。
  5. 丟到 ChatGPT、Gemini、Claude 三個模型測試並比較。
# 角色：你是擅長寫技術部落格的大學生
# 任務：介紹我用 Unity 做的《Overcooked》料理遊戲
# 讀者：想學 Unity 的同學
# 語氣：第一人稱、輕鬆，但每段有重點
# 長度：600～800 字，4 個小段落
# 必須包含：遇到的問題與解法（Play 模式修改不會存檔、
#           用 Inspector 欄位調數值）

我的作業

主題是介紹我自己做的 Unity《Overcooked》料理遊戲：我寫了角色移動、拿放物品、切菜煮菜擺盤、訂單判定、計時與計分。透過反問把讀者、語氣、長度都定下來，最後在三個 LLM 測試。

踩雷與提醒

不要一次塞太多要求條列分段寫，比一大段話更不容易被 AI 漏掉。
每個模型的預設風格不同同一個 Prompt 在不同模型長度、語氣會差很多，要實測，不能只看一個。
