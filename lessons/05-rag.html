第7週 RAG

RAG：讓 AI 讀你的資料再回答

先找資料，再生成答案，降低亂掰的機率。

本週重點

  • RAG（Retrieval-Augmented Generation）= 檢索 + 生成。
  • 文件先切段，再轉成向量存進向量資料庫。
  • 使用者提問時找出最相近的幾段，連同問題一起交給 LLM。
  • 作業分兩份 Colab：RAG01 建資料庫、RAG02 做問答。

核心概念

LLM 不知道你的私人資料，也可能過時。RAG 的做法是把文件切成小段，用Embedding 模型把每段轉成一串數字（向量），意思相近的句子向量也會接近。

提問時把問題也轉成向量，找出距離最近的 k 段，塞進 Prompt：「請根據以下資料回答……」。這樣答案有根據，也比較不會幻覺。

比喻像開書考：LLM 是很會寫作文的學生，RAG 幫它先翻到課本對的那幾頁，再讓它作答。

實作流程

  1. 選一份文件當知識來源。
  2. RAG01：切段 → embedding → 建向量資料庫 → 打包成 rag-data.zip。
  3. RAG02：下載並解壓 rag-data.zip，載入資料庫。
  4. 問題 → 檢索相關段落 → 組 Prompt → LLM 回答。
  5. 用 Gradio 做成對話介面測試。
docs = retriever.invoke(question)          # 找最相近的段落
context = "\n\n".join(d.page_content for d in docs)
prompt = f"""請只根據以下資料回答，找不到就說不知道。
資料：
{context}

問題：{question}"""
answer = llm.invoke(prompt)

我的作業

我的知識來源是童軍技能：童軍諾言、繩結、旗語。改寫老師的 RAG01 建出向量資料庫，再用 RAG02 做成可以問童軍技能的機器人。

踩雷與提醒

切段大小會影響結果切太大檢索不準、切太小上下文不夠，要實際試幾種。
zip 路徑對不上RAG02 解壓後的資料夾名稱要跟程式裡載入的路徑一致。
